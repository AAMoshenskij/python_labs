# Использование ИИ

## Инструменты

- Claude (Anthropic): чат и Claude Code (desktop-приложение).

## Для чего использовался

**Разработка**

- Выбор траектории Python Core и план реализации по условию ЛР 1 и ноутбуку курса.
- Черновик кода пакета: модели (`models.py`), разбор JSON и валидация (`parser.py`, `validation.py`),
  хеширование, in-memory репозиторий, сервис приёма, источники JSONL и in-memory, импорт и CLI.
- Этап Б: контракт `Analyzer`, `LengthAnalyzer`, `TemplateAnalyzer`, третий анализатор
  `DeclarationAnalyzer`, реестр фабрик, `AnalysisService`, проверка отчёта на границе.
- Углубление: загрузка анализаторов через entry points, декоратор `@timed`.
- Тесты, `README.md`, `REPORT.md`, скрипты `defense_demo.py` и `measure.py`.
- Файлы `data/invalid_submissions.jsonl` и `data/assignments.json` (составлены по описанию из ноутбука);
  `data/submissions.jsonl` взят из ноутбука курса.

**Проверка перед сдачей**

- Сверка проекта с требованиями PDF и чек-листом ноутбука (раздел 29).
- Исправление теста `test_invalid_json_is_format_error`: на Windows имя параметра `"[" * 100000`
  превышало лимит длины переменной окружения, и `pytest` падал с ошибкой. Параметру задан короткий id.
- Удаление устаревших файлов: папки `build/` со старой версией кода и семи файлов-заглушек.
- Замеры `scripts/measure.py` на моём компьютере и обновление таблицы в `REPORT.md`.

## Что проверено

- `pytest` — 158 тестов проходят; `mypy` (strict) — без замечаний; `ruff check .` — без замечаний
  (Windows 11, Python 3.15.2).
- Самостоятельно запущены и просмотрены результаты:
  - `school-intake import data\submissions.jsonl` — 12 accepted, ошибок нет;
  - `school-intake import data\invalid_submissions.jsonl` — 11 ошибок с `line_no`, `code`, `field`,
    `message`, корректная строка принята, импорт не останавливается;
  - `school-intake analyze ...` — отчёты `length` и `template` с `analyzer_id`, `analyzer_version`,
    `config_hash`; номера строк в `evidence` сверены с исходным кодом сдач (например, sub-007,
    где пустая строка 2 пропущена);
  - `python scripts\defense_demo.py` — успешный импорт, duplicate, conflict, подключение третьего
    анализатора без изменения `AnalysisService`;
  - `python scripts\measure.py 3000`.
- Чистая установка `pip install .` в новом виртуальном окружении.

## Что изменено после ИИ

- Код анализаторов и сервисов вручную не переписывался; исправления внесены по результатам проверки
  (тест для Windows, удаление устаревших файлов, замеры с моего компьютера).

## Замечания

- Накладные расходы декоратора `@timed` (≈ 10 мкс на вызов) меньше шума измерения: при повторном
  запуске `measure.py` разница получилась отрицательной (−8,5 мкс). Скрипт делает по одному прогону
  с декоратором и без, поэтому знак разницы случаен; вывод — накладные расходы пренебрежимо малы.
- ИИ не использовался для анализа реальных работ студентов; в данных только учебные примеры из ноутбука.
- Токены, пароли и персональные данные в репозиторий не добавлялись.
